---
name: decomp-ticket-gen
description: Write one ticket per in-scope decomp function from the inventory, and mirror progress to GitHub when the contract enables it. Use when decomp-start reaches tickets, or after the inventory or units change.
---

One ticket per in-scope function, generated by script: no ticket is written by hand.

1. Run `python tools/decomp.py gen-tickets`. A new ticket starts `open`; an existing one keeps its status, claim, and notes.
2. Check: the number of tickets equals the number of in-scope functions in `inventory.json`, and every ticket's `expected` file exists.
3. If `decomp.json` enables GitHub, run `python tools/decomp.py sync`. It creates or updates one issue per unit (a checklist of its functions) and one pinned progress issue, rebuilding each body from the ticket files. The ticket files are the source of truth; the issues are a mirror that only `sync` writes.

**Done when** both checks pass and, with GitHub enabled, `sync` reports every unit.
